## Шаг владельца (точное действие, блокер релиза)

Без этого выпуск в production невозможен. Доступы передаются только через
файл `.env.supabase` в корне рабочей папки (добавлен в `.gitignore`, в git не попадает),
созданный по шаблону `.env.supabase.example`.

1. Создать **отдельный проект Supabase для ярмарки** в **новой организации** (Free, $0) —
   иначе превышается лимит бесплатного тарифа (2 активных проекта уже заняты «Межгородом Онлайн»).
   Регион — ближе к Владивостоку (например `ap-northeast-1` Токио или `ap-southeast-1` Сингапур).
2. В Supabase Dashboard → Account → Access Tokens создать **Personal Access Token**.
3. Скопировать в `.env.supabase` (значения — в Dashboard → Project Settings → API):
   - `SUPABASE_ACCESS_TOKEN`
   - `SUPABASE_PROJECT_REF`
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (секрет — только для серверных скриптов)
   - `FAIR_ADMIN_EMAIL` (e-mail администратора ярмарки)
   - `FAIR_ADMIN_PASSWORD` — оставить пустым: надёжный уникальный пароль сгенерирует
     и передаст владельцу исполнитель при создании пользователя (слабые пароли в
     production не используются; `admin/123456` допустим только в изолированном
     синтетическом тесте).
4. Сообщить, что доступы готовы. Дальше исполнитель: применяет миграции и seed,
   разворачивает Edge Function, создаёт администратора с надёжным паролем, прогоняет
   облачный E2E `tools/qa/supabase-e2e.cjs`, затем выполняет релиз ниже.

## Релиз (только после разрешения владельца)

1. **Backend:** проект ярмарки активен; аноним видит только опубликованные мероприятия и `public_registry` (`id`, `name`, `products`); запись/служебные поля — только администратору (RLS).
2. **Код:** открыть Draft PR #6 из `feature/fair-admin-events` в `main` и выполнить merge. GitHub Pages публикует `main` автоматически; действующий домен загружает Pages через iframe (блоки Tilda не меняются).
3. **Переключение бэкенда:** в блоке Tilda T123 (не в репозитории) задать `backend = 'supabase'`, `supabaseUrl`, `supabaseAnonKey`; загрузчик добавит их в `src` iframe как query-параметры, а `js/fair-config.js` подхватит и сохранит в `localStorage` (см. `tilda-loader-template.html`, `docs/ADMIN_SETUP.md`). Anon-ключ публичный, но по правилу проекта в репозиторий не помещается; `service_role` в браузер не попадает.
4. **Проверка на live:** афиша `/events.html`, реестр (только name/products публично), вход в `/admin/`, загрузка/скачивание документа, приказ №54-од и формы без авторизации.

## Откат (при проблеме после релиза)

1. **Код:** revert merge-коммита в `main` — Pages вернёт предыдущую версию сайта. Запасной вариант — восстановить предыдущий `main` из резервной копии блока T123 (`backup/`).
2. **Бэкенд:** вернуть `backend: "static"` (сайт снова читает локальные JSON без Supabase) — мгновенный откат зависимости. Supabase-проект при необходимости приостановить.
3. **Данные:** журнал `change_log` фиксирует изменения; ежедневные резервные копии Supabase (платформа) — точка восстановления.
