# План релиза и отката — Ярмарка «4 сезона» (PR #6, backend REG.RU)

Статус: **разрешение владельца на публикацию получено (26–27.11.2026)**. Прежний план
Supabase отменён решением владельца — backend/auth/storage адаптирован на REG.RU
(PHP 8.1+ / PDO SQLite) без дополнительных расходов. Интерфейс, Tilda и GitHub не меняются.

## Предусловия (до релиза)

- REG.RU-хостинг для ярмарки готов и **изолирован** от MOZGIKOM LAB и «Межгорода Онлайн»:
  отдельный сайт/поддомен (или каталог с отдельной FTP/SSH-учёткой), PHP 8.1+ с `pdo_sqlite`
  и `mbstring`, HTTPS.
- Развёрнуто содержимое `php/public/` (front controller `index.php` + `.htaccess`),
  создан `yarmarka-private` вне webroot (0700), выполнен `php/cli/install.php`
  (схема, seed 102 + демо-мероприятия, администратор с `password_hash`).
- Локальные проверки пройдены: API E2E (`tools/qa/php-api-e2e.cjs`) и браузерный E2E
  (`tools/qa/php-frontend-e2e.cjs`) на синтетических данных.
- Live E2E `tools/qa/php-api-e2e.cjs` пройден против боевого API (после появления доступа).

## Шаг владельца (точное действие, блокер релиза)

Без этого выпуск в production невозможен. Доступы передаются только через локальный
файл `.env.regru` в корне рабочей папки (добавлен в `.gitignore`, в git не попадает),
**не в чат**.

1. Предоставить REG.RU-хостинг для ярмарки, отдельный от LAB/Межгорода (без платных
   услуг — можно отдельный поддомен/каталог на уже оплаченном аккаунте REG.RU).
   Требования: PHP 8.1+, `pdo_sqlite`, `mbstring`, HTTPS.
2. Передать способ развёртывания: FTP over TLS (хост + логин) или SSH/SFTP — в `.env.regru`
   (пароль/ключ в этот файл, не в чат).
3. Указать публичный URL API (например `https://api.4сезона.online`).

Дальше исполнитель: размещает `php/public/`, создаёт `yarmarka-private` вне webroot,
выполняет `install.php` (создаёт администратора с надёжным паролем и передаёт его
владельцу безопасно), прогоняет live E2E, затем выполняет релиз ниже.

## Релиз (только после разрешения владельца и успешных тестов)

1. **Backend:** API активен; аноним видит только опубликованные мероприятия и реестр
   `id`/`name`/`products`; служебные поля, запись и журнал — только по ролям
   (`admin` — всё, `editor` — только мероприятия).
2. **Код:** открыть Draft PR #6 из `feature/fair-admin-events` в `main` и выполнить merge.
   GitHub Pages публикует `main`; `/admin/` появится на Pages. Блоки Tilda не меняются.
3. **Переключение бэкенда:** в блоке Tilda T123 задать `backend = 'php'` и
   `apiBase = 'https://<api-хост>/api'`; `js/fair-config.js` подхватит параметры и
   сохранит в `localStorage` (см. `docs/REG_RU_SETUP.md`).
4. **Проверка на live:** афиша `/events.html`, реестр (только name/products публично),
   вход в `/admin/`, создание/публикация мероприятия, загрузка документа, приказ №54-од
   и формы без авторизации.

## Откат (при проблеме после релиза)

1. **Код:** revert merge-коммита в `main` — Pages вернёт предыдущую версию. Запасной
   вариант — восстановить предыдущий `main` из резервной копии блока T123 (`backup/`).
2. **Бэкенд:** вернуть `backend: "static"` в блоке Tilda — сайт снова читает локальные
   JSON без бэкенда (мгновенный откат зависимости). PHP-API при необходимости
   приостановить.
3. **Данные:** `php/cli/restore.php --from=<снимок>` восстанавливает SQLite/config/uploads
   из резервной копии; журнал `change_log` фиксирует изменения.
